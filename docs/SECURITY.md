# 安全与隐私说明

## 威胁模型与信任边界

Luna 是单用户、自托管应用，不是多租户身份系统。`APP_PASSWORD` 建立一个共享用户身份；签名的 `HttpOnly; Secure; SameSite=Strict` Cookie 对应 D1 中的会话哈希。能读取 D1、部署环境、Cloudflare 账号或主机文件的人属于管理员信任域，可能访问私人数据。

主要边界是：浏览器 ↔ Pages Functions ↔ D1 / 模型或语音提供方。本地开发时，Wrangler D1 保存在 `.wrangler/state`；云端时存于绑定名 `DB` 的 D1。API Key、登录密码和会话签名密钥只允许存在于服务端环境，不进入 `VITE_*`、前端响应、备份或仓库。

## 模型与模式

- `APP_MODE=local` + Ollama 时，文本只发送到显式配置的回环聊天端点。不可达、模型缺失或不兼容都会明确失败。
- 系统不会静默把本地对话转发给 DeepSeek。云端覆盖需要请求同时给出云提供方与明确确认，且仍受服务端配置约束。
- 云端提供方会收到组装后的上下文，包括本轮实际召回的记忆。使用者应遵守提供方的数据政策。
- 可选本地 embedding 只接受回环 HTTP(S)，有短超时；不可用时回退到确定性关键词/分类排序。

## 记忆隐私

自动保存使用结构化候选、确定性敏感扫描和仓储约束。密码、验证码、令牌、身份与支付信息不会自动保存；健康和亲密内容只有在可信用户输入明确确认后才可保存。模型输出本身不能授予确认，也不能直接替换旧记忆。冲突停用要求新鲜读取并核对确认的旧记忆 ID。

每轮只把排序后、数量受限且真正选中的记忆注入上下文。SSE `meta.usedMemories` 只返回这些 ID 与经过控制字符清理、截断的展示文本，界面默认折叠为“本次使用的记忆”；它不是全部候选或模型内部推理记录。

## 记忆备份与恢复

备份含真实长期记忆文本，应按私人聊天数据保护。它不含对话、消息、会话、Cookie、API Key、环境配置、数据库 ID 或来源 ID。格式严格版本化，最多 1,000 条，导入请求/可导出导入信封最多 2 MiB；服务端在任何写入前验证整份 JSON、未知字段、类型、时间和分值，并要求 `confirmation: true`。

恢复会规范化、去重并使用确定性 ID 和数据库防重复条件。D1 没有包住整份最多 1,000 条备份的全局事务：按批写入时若后批失败，前批可能已存在；同一文件可安全重试以补齐，不会成倍复制。恢复前仍应备份现状，并检查接口返回的 `created` / `skipped`。

## 语音边界

- 浏览器语音默认在浏览器的 Web Speech 实现中运行；操作系统或浏览器厂商如何处理文本取决于其实现。
- 本地模式的 `LOCAL_TTS_ENDPOINT` 只接受无凭据、无查询/片段的 loopback HTTP(S)。
- 云端模式只接受外部 HTTPS 公共 FQDN；请求严格来自部署者环境变量，API 或保存的 UI 数据不能提供 URL。请求使用 `redirect: error`，只接受 `audio/*`，响应上限 10 MiB，并有超时。
- 公共 FQDN 检查只能阻止常见误配置，不能证明 DNS 解析目标、域名所有权或服务可信。能控制部署变量或 DNS 的人可改变目的地，TTS 运营者能看到朗读文本。需要更强保证时在网络层增加固定出站策略和受控网关。
- MiniMax 是可选云服务，只有选择该提供方时文本才发往 MiniMax。

## 密钥扫描与仓库边界

`npm run check:secrets` 扫描当前候选文件和全部可达 Git 历史 blob，检查常见 `sk-*`、GitHub token、AWS access key、私钥块及 Luna 环境变量赋值；同时拒绝日志、私钥、数据库、模型和音频文件以及 `.wrangler` 等目录。仅有两个精确的公开测试 fixture 被允许：一个示例 `sk-` token 和 AWS 官方示例 access key；允许逻辑刻意在扫描器源码中分段，其他同形值仍会失败。

不要提交 `.dev.vars`、`.env`、`.wrangler/state`、`*.sqlite`/`*.db`、日志、模型权重（如 GGUF/Safetensors/ONNX）或语音/音频文件。仓库只保留 `*.example` 示例，不应填入真实值。若凭据进入 Git 历史，删除文件不等于撤销：应立即在供应商处轮换、评估暴露并按托管平台流程清理历史。

## 运行日志与数据库

服务端错误日志只应记录请求 ID、稳定错误码和必要诊断，不记录消息、记忆、Cookie、Authorization、密钥、完整上游响应或 TTS 文本。Cloudflare 日志、D1、备份文件、本地 `.wrangler/state` 和浏览器音频缓存都应配置合适的访问控制与保留期限。生产数据库备份与恢复由部署者负责。

## 漏洞报告

不要在公开 Issue 中粘贴漏洞利用细节、私人对话、数据库或密钥。仓库启用 GitHub Security Advisories 时优先使用私密 “Report a vulnerability”；否则通过仓库所有者公开的私密安全联系方式仅发送最小复现、受影响提交/版本和影响说明。先轮换可能泄露的凭据，再讨论修复；未经授权不要测试他人部署或真实账号。
