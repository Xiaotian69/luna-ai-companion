# Luna 混合式 AI 伴侣设计规格

日期：2026-07-25  
状态：设计已批准；Tasks 1–13 已实现并通过复审，等待 Task 14 发布（尚未宣称 GitHub 已发布）

## 1. 背景

Luna 当前是一套单用户中文 AI 陪伴网页，使用 React、Cloudflare Pages Functions、Cloudflare D1、DeepSeek 文本模型和 MiniMax 语音模型。现有聊天、历史记录、摘要、长期记忆、语音、登录、限流和用量管理已经可用。

本次升级把项目整理为可公开复用的 AI 伴侣项目：

- Luna 保留为默认示例，但使用者可以自由修改名字、关系、性格、称呼、头像和声音。
- 支持女友、男友、朋友及自定义关系，不把角色能力与性别绑定。
- 保留现有 UI 作为主要交互，不进行全量视觉重构。
- 新增本地优先模式，让日常聊天可以使用用户电脑上的开放权重模型，不产生商业模型 Token 账单。
- 保留 DeepSeek、MiniMax 等云端服务作为使用者自行配置的可选增强。
- 将长期记忆作为项目的核心特色，强调透明、可编辑、可撤销和隐私优先。
- 公开仓库不包含原项目所有者的 API Key、密码、聊天数据、模型文件或音色文件。

## 2. 目标

### 2.1 产品目标

1. 使用者能在网页内完成伴侣设置，不需要修改源代码。
2. 本地模式和云端模式共用一套界面与智能体行为。
3. 本地模式默认不向任何商业模型发送聊天内容。
4. 模型提供语言生成能力；项目自身负责角色、记忆、关系状态和上下文编排。
5. 长期记忆的来源、内容和使用方式对使用者透明。
6. 项目可以安全发布为公开 GitHub 仓库，并允许他人填写自己的服务密钥。

### 2.2 工程目标

1. 把模型、语音、存储和智能体核心拆成边界明确的模块。
2. 保持现有前端 API 契约，避免为本地与云端维护两套界面。
3. 使用相同的逻辑数据结构映射 Cloudflare D1 与本地 SQLite。
4. 对角色设置、记忆治理、隐私过滤和提供商切换建立自动化测试。
5. 为本地模式、Cloudflare 模式和可选云端服务提供完整文档。

## 3. 非目标

本次版本不包含：

- 从零训练语言模型或语音模型。
- 在仓库内分发大模型权重或第三方音色文件。
- 多角色创建与角色市场。
- AI 自动生成或克隆真人头像。
- 自动把本地失败请求转发给云端。
- 全量改版现有聊天 UI。
- 多用户账号、社交广场、内容推荐或付费系统。
- 移动端原生应用。

这些内容进入独立的未来路线图，不影响本次公开版本完成。

## 4. 运行模式

### 4.1 本地优先模式

```text
React 前端
    ↓ 同源 /api
本地 Node 智能体服务
    ├── 智能体核心
    ├── 本地 SQLite
    ├── Ollama / llama.cpp 兼容文本接口
    └── 系统语音或可选本地 TTS
```

本地服务仅监听 `127.0.0.1`。聊天、角色和记忆保存在用户电脑中。默认模型名称和本地模型地址通过本地环境变量配置，使用者可自行更换。

启动入口：

```text
npm run dev:local
```

### 4.2 云端模式

```text
React 前端
    ↓ 同源 /api
Cloudflare Pages Functions
    ├── 智能体核心
    ├── Cloudflare D1
    ├── DeepSeek 文本模型
    └── MiniMax TTS
```

云端密钥只存在于 Cloudflare Secret 或本地 `.dev.vars`，不会进入浏览器构建产物。

启动入口：

```text
npm run dev:cloud
```

### 4.3 明确切换

本地模型不可用时，界面显示原因和修复建议。只有使用者明确选择“本次使用云端”后，当前内容才可以发往云端。系统不得静默降级或自动上传。

## 5. 模块划分

### 5.1 共享智能体核心

共享核心负责：

- 合并基础安全规则与自定义伴侣档案。
- 组装关系状态、相关长期记忆、对话摘要和最近消息。
- 限制上下文大小并压缩旧内容。
- 生成记忆候选与摘要请求。
- 对模型输出执行结构化校验。
- 向前端返回本轮实际使用的记忆标识。

共享核心不得直接依赖 Cloudflare D1、Node SQLite、DeepSeek 或 Ollama。存储与模型能力通过接口注入。

### 5.2 文本提供商

统一文本接口支持：

- DeepSeek 云端适配器。
- Ollama 或 llama.cpp 的本地兼容适配器。

适配器负责流式输出、取消请求、错误归一化和模型标识；角色与记忆逻辑不得放入适配器。

### 5.3 语音提供商

统一语音接口支持：

- 浏览器或操作系统已有语音。
- 使用者自行安装的本地 TTS。
- 使用者自行配置的 MiniMax TTS。

声音与角色性别不绑定。界面仅显示提供商返回或本机检测到的可用声音。仓库不分发第三方音色文件。

### 5.4 存储提供商

统一存储能力映射：

- Cloudflare D1。
- 本地 SQLite。

两者使用同一套逻辑实体：对话、消息、摘要、伴侣档案、长期记忆、关系状态和使用记录。

## 6. “我的 AI 伴侣”

在现有导航中增加独立入口“我的 AI 伴侣”。页面支持：

- 名字。
- 头像图片 URL；无头像时显示名字首字。
- 关系预设：女友、男友、朋友、自定义。
- 自定义关系名称。
- 对用户的称呼。
- 性格描述。
- 说话风格。
- 相处边界。
- 语音提供商与音色。
- 保存后的简短回复预览。

Luna 是默认示例。首次登录仅显示轻量提示卡，引导进入该页面；不增加强制多步骤向导。

高级字段默认折叠。现有聊天页面不增加大面积配置面板。

## 7. 长期记忆系统

### 7.1 记忆分类

长期记忆分为四个面向使用者的类别：

1. 关于你：稳定身份、偏好、重要人物和长期目标。
2. 一起经历：重要事件、纪念日和持续话题。
3. 约定与待续：承诺、计划和未完成事项。
4. 关系状态：熟悉度、近期情绪、相处方式和明确边界。

### 7.2 写入流程

```text
对话完成
  → 模型产生结构化候选
  → 敏感信息过滤
  → 用户隐私规则检查
  → 去重与冲突检测
  → 重要度评估
  → 保存来源、时间和置信信息
```

同一事实重复出现时提高可信度，不创建重复记录。新信息与旧信息冲突时更新有效信息，并保留可追踪的修改时间，不把两个冲突事实同时注入上下文。

### 7.3 召回流程

本地模式优先使用本地嵌入模型进行语义检索；不可用时使用关键词、类别与时间排序。召回综合考虑：

- 与当前输入的语义相关性。
- 记忆重要度。
- 最近更新时间。
- 最近使用次数。
- 是否属于未完成事项。

每轮只注入有限数量的相关记忆，避免小模型因上下文过长而变慢或偏离角色。

### 7.4 透明度与控制

记忆中心显示：

- 记忆内容与类别。
- 来源对话。
- 创建和更新时间。
- 重要度。
- 使用次数与最近使用时间。
- 当前是否启用。

使用者可以编辑、停用、启用、删除、全部清空、导出和恢复本地备份。

助手回复提供折叠的“本次使用的记忆”区域，只显示实际注入的记忆，不声称使用未被召回的内容。

### 7.5 隐私边界

以下内容永不自动保存：

- 密码、验证码和访问密钥。
- 身份证、护照、银行卡和支付信息。
- 可用于直接认证或控制账号的数据。

亲密内容、健康信息和其他高敏感内容默认不自动进入长期记忆。使用者可以启用“保存前询问我”，由界面确认后再保存。

> 当前实现状态（2026-07-28）：上述“保存前询问我”仍是设计目标。服务层保留可信确认参数，但聊天 API 和界面尚未暴露；因此健康、亲密等敏感候选当前会被阻止自动保存。

## 8. UI 约束

1. 延续当前聊天 UI、主题、布局与响应式行为。
2. 新功能通过现有导航进入独立页面。
3. 高级设置、记忆来源和诊断信息默认折叠。
4. 聊天页只增加：
   - 当前运行模式标识。
   - 本地服务异常提示。
   - 可折叠的本轮记忆来源。
5. UI 的整体视觉重做延后，不阻塞本次功能发布。

## 9. 错误处理

本地模式需要区分：

- 本地智能体服务未启动。
- Ollama 或兼容服务未启动。
- 指定模型尚未下载。
- 模型加载失败或内存不足。
- 本地 SQLite 无法打开或迁移失败。
- 本地 TTS 未安装或音色文件缺失。

错误信息必须提供可执行的修复步骤，不直接显示内部堆栈或密钥。

云端模式保留并细化：

- 未配置 API Key。
- 上游鉴权失败。
- 上游余额不足。
- 限流与每日用量上限。
- 网络中断和流式响应中止。

## 10. 安全要求

- 本地服务默认只绑定环回地址。
- 所有 JSON 输入继续使用服务端 Schema 校验。
- API Key 不进入前端状态、LocalStorage、日志、数据库或错误消息。
- `.dev.vars`、本地数据库、模型目录、音色目录和可视化草稿被 Git 忽略。
- 发布前执行工作树和 Git 历史密钥扫描。
- 本地请求不得自动回退云端。
- 敏感记忆遵循默认不保存和显式确认原则。
- 公开仓库只包含示例变量名、用途、申请地址与配置步骤。

## 11. 测试策略

### 11.1 单元测试

覆盖：

- 伴侣档案校验与默认值。
- 自定义关系与称呼。
- 人格提示词组装。
- 记忆候选结构化解析。
- 敏感与高敏感记忆过滤。
- 记忆去重、冲突更新和排序。
- 模式切换必须显式确认。
- 提供商错误归一化。

### 11.2 集成测试

覆盖：

- 本地 SQLite 迁移与仓储操作。
- D1 迁移与仓储操作。
- Ollama/llama.cpp 兼容流式接口。
- DeepSeek 流式接口。
- 本地和云端使用同一 API 契约。
- 本地服务不可用时不会触发云端请求。

### 11.3 端到端测试

继续覆盖桌面端和移动端现有聊天体验，并增加：

- 打开“我的 AI 伴侣”、修改名称并保存。
- 在聊天导航与回复中显示新名称。
- 查看、编辑、停用和删除记忆。
- 展开本轮使用的记忆。
- 显示本地服务诊断信息。

真实商业 API 不进入 CI。真实本地模型测试作为可选烟雾测试运行。

## 12. 文档与公开发布

公开仓库名称使用 `luna-ai-companion`，Luna 仅作为默认示例角色。

仓库包含：

- 中文优先的 README。
- 本地优先模式快速开始。
- Cloudflare 模式部署步骤。
- `.dev.vars.example` 与本地环境变量示例。
- DeepSeek、MiniMax、Cloudflare、Ollama/llama.cpp 和本地 TTS 的官方申请或安装链接。
- 不同内存档位的模型选择建议，并明确实际速度依赖硬件。
- 记忆功能特色与隐私说明。
- 架构图与功能截图。
- MIT License，且明确第三方依赖、模型和音色适用各自许可证。
- 独立 `ROADMAP.md`。

公开前必须：

1. 检查 Git 状态和提交范围。
2. 运行密钥扫描。
3. 运行类型检查、Lint、单元测试、集成测试、生产构建和端到端测试。
4. 确认本地配置、数据库、模型、音色、日志和截图草稿未被跟踪。
5. 创建公开 GitHub 仓库并推送验证后的提交。

## 13. 未来路线图边界

未来路线图单独记录并单独向用户展示，候选方向包括：

- 多角色与角色切换。
- 本地模型自动检测、下载和性能基准。
- 更丰富的关系成长与事件时间线。
- 本地语音训练、音色克隆和实时语音对话。
- 图片、语音和文件记忆。
- 多设备加密同步。
- 移动端与桌面端应用。
- 插件、工具调用和主动任务。
- 记忆可视化图谱。

这些方向不进入本次验收范围。

## 14. 验收标准

项目达到公开发布要求时：

1. 默认 Luna 能正常聊天，且可在网页内改名和修改性格。
2. 女友、男友、朋友与自定义关系均可保存并影响提示词。
3. 本地模式可以使用本机开放权重模型完成流式聊天。
4. 本地模式不配置任何商业 API Key 也能完成文字聊天与本地记忆。
5. 云端模式继续支持使用者自己的 DeepSeek 与 MiniMax Key。
6. 本地失败不会自动泄露请求到云端。
7. 长期记忆可分类查看、编辑、停用、删除、清空、导出和恢复。
8. 回复可以显示实际使用的记忆。
9. 现有聊天 UI 与移动端布局没有被整体替换。
10. 仓库密钥扫描、类型检查、Lint、测试、构建和端到端检查通过。
11. 公开仓库不包含项目所有者的真实密钥、密码、聊天数据或本地数据库。
12. README 能让新用户分别完成本地模式和 Cloudflare 模式启动。
